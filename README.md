# Планировщик задач

Учебный веб-сервер на Go для ведения списка задач. Позволяет создавать, просматривать, редактировать, искать, удалять и завершать задачи. Данные хранятся в SQLite, интерфейс доступен в браузере.

При завершении одноразовая задача удаляется, а повторяющаяся переносится на следующую дату по своему правилу.

## Выполненные задания со звёздочкой

- Правила повторения по дням недели (`w`) и дням месяца (`m`), включая выбор месяцев, последний и предпоследний дни месяца
- Поиск задач по заголовку, комментарию или дате в формате `ДД.ММ.ГГГГ`
- Настройка порта и пути к БД через переменные окружения
- Вход по паролю с JWT-токеном на 8 часов
- Dockerfile для сборки и запуска приложения

## Локальный запуск

Требуется Go 1.26.0 или новее. Все команды выполняются из корня проекта: сервер читает файлы интерфейса из `./web`.

```bash
go mod download
go run .
```

Откройте **http://localhost:7540**. База `scheduler.db` и её схема создаются автоматически, если их ещё нет.

Приложение настраивается через переменные окружения, дополнительных флагов нет:

| Переменная | Назначение | По умолчанию |
| --- | --- | --- |
| `TODO_PORT` | Порт HTTP-сервера, от 1 до 65535 | `7540` |
| `TODO_DBFILE` | Путь к файлу SQLite; родительская директория должна существовать | `scheduler.db` |
| `TODO_PASSWORD` | Пароль входа; пустое значение отключает авторизацию | пустое значение |
| `TODO_JWT_SECRET` | Секрет подписи JWT, минимум 32 байта; обязателен при заданном пароле | пустое значение |

Например, запуск на другом порту с отдельной базой:

```bash
TODO_PORT=8080 TODO_DBFILE=./tasks.db go run .
```

В этом случае адрес в браузере — **http://localhost:8080**.

### Запуск с паролем

Можно создать локальный `.env` со следующими значениями:

```dotenv
TODO_PORT=7540
TODO_DBFILE=./scheduler.db
TODO_PASSWORD='replace-with-your-password'
TODO_JWT_SECRET='replace-with-a-random-secret-at-least-32-bytes'
```

Замените пароль и секрет своими значениями. Случайный секрет можно получить командой `openssl rand -hex 32`. Не добавляйте `.env` в репозиторий.

Приложение не читает `.env` автоматически. Для загрузки файла в Bash:

```bash
set -a
source .env
set +a
go run .
```

Страница входа: **http://localhost:7540/login.html**. После изменения пароля или секрета перезапустите сервер и войдите заново.

## Запуск тестов

Тесты из `tests` обращаются к работающему HTTP-серверу и напрямую к его базе. Они изменяют данные, включая удаление всех задач, поэтому используйте отдельную тестовую БД.

Значения в `tests/settings.go` для полной проверки:

```go
var Port = 7540
var DBFile = "../scheduler.db"
var FullNextDate = true
var Search = true
var Token = ``
```

`FullNextDate` включает проверку недельных и месячных правил, `Search` — поиска. `Token` оставьте пустым при отключённой авторизации. Для проверки с паролем укажите в нём действующий JWT из поля `token` ответа `POST /api/signin`.

Переменные `TODO_PORT` и `TODO_DBFILE` переопределяют `Port` и `DBFile`. У сервера и тестов должны совпадать порт и абсолютный путь к БД.

Первый терминал — сервер с отдельной тестовой базой и отключённой авторизацией:

```bash
TODO_PORT=7540 TODO_DBFILE=/tmp/go-final-test.db TODO_PASSWORD= go run .
```

Второй терминал — все интеграционные тесты:

```bash
TODO_PORT=7540 TODO_DBFILE=/tmp/go-final-test.db go test -count=1 ./tests
```

Для отдельного теста добавьте фильтр:

```bash
TODO_PORT=7540 TODO_DBFILE=/tmp/go-final-test.db go test -count=1 -run '^TestAddTask$' ./tests
```

## Docker

Соберите образ из корня проекта:

```bash
docker build -t go-final .
```

Создайте том для базы и запустите контейнер:

```bash
docker volume create go-final-data
docker run -d --name go-final \
  -p 7540:7540 \
  -v go-final-data:/data \
  go-final
```

Откройте **http://localhost:7540**. В контейнере БД хранится в `/data/scheduler.db`; том сохраняет её после удаления контейнера. Приложение работает от пользователя с UID `10001`.

Для запуска с паролем сначала экспортируйте `TODO_PASSWORD` и `TODO_JWT_SECRET` в терминале, например загрузив `.env`, как показано выше. Затем добавьте их в команду запуска:

```bash
docker run -d --name go-final \
  -p 7540:7540 \
  -v go-final-data:/data \
  -e TODO_PASSWORD \
  -e TODO_JWT_SECRET \
  go-final
```

Выберите один из вариантов запуска; если контейнер `go-final` уже существует, сначала остановите и удалите его. Именованный том при этом сохраняется.

Для изменения внешнего порта замените `-p 7540:7540` на `-p 8080:7540` и откройте **http://localhost:8080**.

Просмотр логов и остановка:

```bash
docker logs go-final
docker stop go-final
```
